# Off Campus Compass — deploy notes for the parent

## What was built

A complete, working off-campus housing + roommate-matching web app for Cornell
students, in `/home/hatch/workspace/projects/off-campus-compass/`:

- **Backend** (`backend/`, Node 24 + Express + JWT auth + bcrypt): listings with
  filters, listing detail + landlord reviews, bookmarks, housing questionnaire,
  transparent roommate matching (0–100 with per-factor reasons), roommate
  requests (send/accept/decline), housemates, accounts. Dual-engine data layer:
  SQLite by default (`backend/data/compass.db`), Postgres when `DATABASE_URL`
  is a `postgres://` URL.
- **Frontend** (`frontend/`, React 19 + TypeScript + Vite, hash routing):
  Home (hero + search + featured), Browse (filters), ListingDetail (facts,
  amenities, landlord reviews + review form, bookmark), Matching (10-question
  form + match cards with score breakdown), Requests (incoming/outgoing +
  housemates), Saved, Post a listing, Auth (login/register + one-click demo
  logins), Profile. Cornell carnelian/cream design with a compass motif.
- **Seed data:** 10 fictional demo listings (Collegetown, West Campus, North
  Campus, East Hill, Fall Creek, South Hill, Downtown, Cayuga Heights — street
  names are real Ithaca geography, no real landlords/phone numbers/house
  numbers) and 6 fictional demo student profiles with filled questionnaires,
  plus demo landlord reviews, bookmarks, and one accepted roommate pair.
  Demo logins (password `demo123`): `demo@offcampuscompass.demo`,
  `jordan@offcampuscompass.demo`, `priya@offcampuscompass.demo`.

Grounded in jem's BigRedHack 2024 Devpost project
(https://devpost.com/software/off-campus-compass — "create profiles… input
their housing preferences and get matched… post reviews of landlords… view
all housing options… avoid having to network extensively with upperclassmen").

## Deploy steps (parent)

1. **Create the GitHub repo** (App cannot create repos — use the browser
   signed in as jem, same as the SOUP repo). Suggested name:
   `Jemimahosei/off-campus-compass`. Then snapshot-push the project root.
   Text-only push is fine: no binary files in the repo (no images; all art
   is CSS/SVG). `node_modules/`, `dist/`, `backend/data/` are gitignored.
2. **Render Blueprint:** sync `render.yaml` from the repo. Two free services:
   `off-campus-compass-backend` (Node, `JWT_SECRET` generated, `DATABASE_URL`
   sync:false) and `off-campus-compass-frontend` (static, publishes
   `frontend/dist`).
3. **Fix the frontend API URL after the backend exists:** the frontend bakes
   `VITE_API_URL` in at build time. After the backend deploys, copy its real
   onrender.com URL (it may get a suffix like `-xxxx`, as Gradebook's did),
   set the frontend service's `VITE_API_URL` to
   `https://<real-backend-url>/api`, and redeploy the frontend.
4. **Database choice:** leave `DATABASE_URL` unset for SQLite (works, but
   data resets on redeploy — seeded demo data re-creates itself on boot), or
   set it to a Neon Postgres URL for persistence. NOTE: the Postgres branch
   of `backend/src/db.js` is code-reviewed but was NOT live-tested in this
   VM (no Postgres available here) — watch the first boot logs if you use it.
   `JWT_SECRET` is generated by Render via the Blueprint; set a real one if
   deploying any other way.
5. **Verify live:** open the frontend, log in as
   `demo@offcampuscompass.demo` / `demo123`, check Browse loads 10 listings,
   open a listing, check Matching shows 5 matches for Maya, and send a test
   roommate request.

## Known limitations

- No email sending (no SMTP): password reset does not exist; demo accounts
  are the way in.
- No real listings data source — listings are user-posted or seeded demos.
- No map view (listings show walk-time to campus instead).
- SQLite on Render free tier is ephemeral across deploys; see step 4.
- The matching algorithm is the replacement implementation (see provenance
  note above), not the teammates' original file.
